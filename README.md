# Intelligent Inventory Dashboard API

Backend REST API for an intelligent dealership inventory dashboard. The service lists vehicle inventory, identifies aging vehicles that have been in stock for more than 90 days, and records manager actions against aging stock.

The application is implemented with Node.js, Express, TypeScript, Prisma, PostgreSQL, and Vitest.

## Prerequisites

- Node.js 20 or newer
- npm
- PostgreSQL database

## Project Structure

```text
prisma/                 Prisma schema, migrations, and seed data
src/
  modules/              Vehicle and action-log API modules
  shared/               Shared middleware, logging, errors, and Swagger config
  app.ts                Express application entry point
package.json            Build, run, and test scripts
```

## Environment Setup

Clone respository & move to working directory

```bash
git clone <repository-url>
cd inventory-dashboard-api
```

Install dependencies:

```bash
npm install
```

Create a local `.env` file:

```bash
cp .env.template .env
```

## Database Setup

Run local PostgreSQL:

```bash
npx prisma dev --name inventory_dashboard --detach
```

- Note: Paste displayed URL after running the above command to file ".env" for `DATABASE_URL`

Generates Prisma Client based on schema.prisma:

```bash
npx prisma generate
```

Apply existing migrations to your local DB:

```bash
npx prisma migrate deploy
```

Seed the database with sample vehicles and action logs:

```bash
npx tsx prisma/seed.ts
```

The seed creates fresh vehicles, aging vehicles, and action history examples for testing the dashboard flows.

## Run in Development

Start the API in watch mode:

```bash
npm run dev
```

By default, the server listens on port `3000`.

- API base URL: `http://localhost:3000/api/v1`
- Swagger UI: `http://localhost:3000/docs`
- OpenAPI JSON: `http://localhost:3000/docs.json`

## Useful API Endpoints

```text
GET  /api/v1/vehicles
GET  /api/v1/vehicles/:id
POST /api/v1/vehicles/:id/actions
```

Example requests:

```bash
curl "http://localhost:3000/api/v1/vehicles?isAging=true&page=1&limit=10"
```

```bash
curl --location --request GET "http://localhost:3000/api/v1/vehicles/<vehicle-id>"
```

```bash
curl -X POST "http://localhost:3000/api/v1/vehicles/<vehicle-id>/actions" \
  -H "Content-Type: application/json" \
  -H "x-user-id: mgr_demo_101" \
  -d '{
    "action": "Price Reduction Planned",
    "notes": "Reducing price due to aging inventory."
  }'
```

Actions can only be logged for vehicles that have been in stock for more than 90 days.

## Notes

- Can test API with predefined Postman collection with `inventory-dashboard-api.postman_collection.json`
- Authentication is stubbed through request headers. Use `x-user-id` to simulate the manager identity for action logging.
- Inventory aging is calculated from `receivedDate`; vehicles older than 90 days are considered aging.
- See `system-design-doc.md` for design assumptions and architecture details.

## Clean up after testing

To STOP the database instance (keep the data, just not running)

```bash
npx prisma dev stop inventory_dashboard
```

To DELETE the database instance (including all its data)

```bash
npx prisma dev rm inventory_dashboard --force
```

## AI Collaboration Narrative

### Strategy

AI was used as an engineering assistant throughout the project to support:

- Analyze requirements and generate initial design ideas - data model, API contract, business rules (e.g. 90-day aging rule) — before writing code.
- Built one module at a time (vehicles → action logs → shared middleware)
- Generate boilerplate code for controllers, services, and tests to accelerate development.
- Generate Swagger documentation and OpenAPI spec from code annotations.

The goal was to accelerate development while keeping all technical decisions under my control.

### Verification & Refinement

All AI-generated suggestions were manually reviewed before adoption.

- Verified against the assignment requirements.
- Cross-checked with official documentation when needed.
- Refined designs to avoid unnecessary complexity.
- Manually test endpoints with curl and Postman to confirm real behavior matched the docs.

### Quality Assurance

The final solution was ensured by:

- Applying engineering judgment instead of accepting AI output directly.
- Following RESTful API and clean architecture principles.
- Validating inputs and handling errors consistently.
- Testing the implemented APIs and reviewing the generated documentation.
- Cross-checked Swagger docs against actual endpoint behavior.
