# Intelligent Inventory Dashboard API

Backend REST API for an intelligent dealership inventory dashboard. The service lists vehicle inventory, identifies aging vehicles that have been in stock for more than 90 days, and records manager actions against aging stock.

The application is implemented with Node.js, Express, TypeScript, Prisma, PostgreSQL, and Vitest.

## Prerequisites

- Node.js 20 or newer
- npm
- PostgreSQL database

## Project Structure

```text
prisma/                 Prisma schema, migrations, and seed data
src/
  modules/              Vehicle and action-log API modules
  shared/               Shared middleware, logging, errors, and Swagger config
  app.ts                Express application entry point
package.json            Build, run, and test scripts
```

## Environment Setup

Install dependencies:

```bash
npm install
```

Create a local `.env` file:

```bash
cp .env.example .env
```

Set the required environment variables:

```env
DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/inventory_dashboard"
LOG_LEVEL="info"
```

Replace `USER`, `PASSWORD`, host, port, and database name with your local PostgreSQL settings.

## Database Setup

Apply the Prisma migrations:

```bash
npx prisma migrate dev
```

Seed the database with sample vehicles and action logs:

```bash
npx tsx prisma/seed.ts
```

The seed creates fresh vehicles, aging vehicles, and action history examples for testing the dashboard flows.

## Run in Development

Start the API in watch mode:

```bash
npm run dev
```

By default, the server listens on port `3000`.

- API base URL: `http://localhost:3000/api/v1`
- Swagger UI: `http://localhost:3000/docs`
- OpenAPI JSON: `http://localhost:3000/docs.json`

You can override the port by setting `PORT`:

```bash
PORT=4000 npm run dev
```

## Build and Run for Production

Create a production build:

```bash
npm run build
```

Run the compiled application:

```bash
npm start
```

The build output is written to `dist/`.

## Test

Run the full test suite once:

```bash
npm test
```

Run tests in watch mode:

```bash
npm run test:watch
```

Run tests with coverage:

```bash
npm run test:coverage
```

Coverage reports are generated by Vitest using the V8 provider.

## AI Collaboration Narrative

I used AI as a structured engineering collaborator rather than as a one-shot code generator. The high-level strategy was to guide the AI with the project requirements, then keep the implementation grounded in simple backend patterns: a TypeScript Express API, Prisma-backed persistence, module-level separation for vehicles and action logs, runtime validation, and automated tests around the core business rules.

The collaboration process followed an iterative loop. I first clarified the domain assumptions, especially how inventory age is calculated, when a vehicle qualifies as aging stock, and whether manager actions should overwrite state or be stored as an audit history. I then used the AI to help shape the service boundaries, route structure, Prisma schema, validation rules, and test cases. After each pass, I reviewed the output against the requirements and refined anything that was too broad, ambiguous, or over-engineered.

Verification was handled through both automated checks and manual review. I ran the Vitest suite to confirm controller and service behavior, including filtering, aging calculations, and action-log rules. I also ran the production build to confirm the TypeScript and bundling pipeline succeeded. Beyond command output, I inspected the README, API routes, Prisma schema, and seed data to make sure the setup instructions matched the actual application behavior.

Final quality was ensured by keeping the scope intentionally tight: the API supports the required dashboard flows, documents the available endpoints through Swagger, persists data with migrations and seed records, and protects the main business rule that actions can only be logged for vehicles older than 90 days. The result is a maintainable assessment-ready backend with clear setup, build, run, and test instructions.

## Useful API Endpoints

```text
GET  /api/v1/vehicles
GET  /api/v1/vehicles/:id
POST /api/v1/vehicles/:id/actions
```

Example requests:

```bash
curl "http://localhost:3000/api/v1/vehicles?isAging=true&page=1&limit=10"
```

```bash
curl -X POST "http://localhost:3000/api/v1/vehicles/<vehicle-id>/actions" \
  -H "Content-Type: application/json" \
  -H "x-user-id: mgr_demo_101" \
  -d '{
    "action": "Price Reduction Planned",
    "notes": "Reducing price due to aging inventory."
  }'
```

Actions can only be logged for vehicles that have been in stock for more than 90 days.

## Notes

- Authentication is stubbed through request headers. Use `x-user-id` to simulate the manager identity for action logging.
- Inventory aging is calculated from `receivedDate`; vehicles older than 90 days are considered aging.
- See `system-design-doc.md` for design assumptions and architecture details.
